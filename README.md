# Codex Mobile App

Mobile companion for using a local Codex setup from an Android device through a
local bridge and a private WireGuard VPN.

The app is an operations client. It does not talk directly to the OpenAI API and
does not import the Codex SDK in the mobile bundle. The desktop remains the
trust boundary: Codex, OpenAI authentication, workspaces, filesystem access, MCP
servers, apps, skills, and approvals all stay on the machine running the bridge.

## Architecture

```text
Android app
  -> http://10.77.77.1:8787
  -> WireGuard tunnel (UDP 51821)
  -> desktop interface wg-codex
  -> Codex Bridge (Node.js + TypeScript)
  -> codex app-server or @openai/codex-sdk
  -> local Codex CLI/runtime
```

The phone joins a private `10.77.77.0/24` network that exists only between
key-authenticated peers, and speaks plain HTTP to the bridge inside it. The only
port reachable from the internet is WireGuard's UDP `51821`. The bridge binds to
`10.77.77.1` and is not reachable from the LAN or the internet.

**No secret is embedded in the APK.** The phone's private key is generated by the
WireGuard app and never leaves the device. Revoking a device is deleting a
`[Peer]` block on the host — no rebuild, no redistribution.

The default runtime is `app-server`, because it supports richer Codex client
behavior: persisted conversations, settings, model/account data, apps, skills,
MCP resources, streamed events, and human-in-the-loop approvals. The SDK runtime
is still available as a simpler adapter. Tests use an isolated fake runtime that
is not included as a production runtime option.

Official Codex references:

- Codex app-server: https://developers.openai.com/codex/app-server
- Codex SDK: https://developers.openai.com/codex/sdk
- Codex CLI reference: https://developers.openai.com/codex/cli/reference

## Stack

- Backend runtime: Node.js
- Backend language: TypeScript
- Backend package manager/scripts: npm
- Mobile app: Expo + React Native + TypeScript
- Remote access: WireGuard, managed by the OS on both ends
- Transport: HTTP/SSE over the private tunnel network

Conventions:

- Desktop bridge inside the tunnel: `10.77.77.1:8787`
- Desktop bridge in local development: `127.0.0.1:8787`
- Phone address inside the tunnel: `10.77.77.2/32`
- WireGuard listen port: UDP `51821`
- Default mobile gateway: `http`
- Default bridge runtime: `app-server`

## Repository Layout

- `backend/`: local Codex Bridge. Exposes the HTTP/SSE API consumed by mobile and
  wraps the selected Codex runtime.
- `mobile/`: Expo/React Native app.
- `build-guide/`: interactive HTML guide for building, installing, securing, and
  troubleshooting the Android APK.

## Backend

```powershell
cd backend
npm install
npm run dev
```

Useful checks:

```powershell
npm test
npm run typecheck
npm run build
npm run smoke:app-server
```

Runtime selection:

```powershell
$env:CODEX_BRIDGE_RUNTIME = "app-server" # default
npm run dev
```

Supported values are:

- `app-server`: uses `codex app-server` over stdio JSON-RPC. Recommended.
- `sdk`: uses `@openai/codex-sdk`.

The bridge listens on `127.0.0.1:8787` by default. For phone access, bind it to
the tunnel address instead:

```powershell
$env:CODEX_BRIDGE_HOST = "10.77.77.1"
$env:CODEX_BRIDGE_PORT = "8787"
node dist/server.js
```

Confirm it with:

```powershell
Invoke-RestMethod http://10.77.77.1:8787/health
Get-NetTCPConnection -State Listen -LocalPort 8787 | Select-Object LocalAddress
```

The second command must show only the address you intended. If it shows
`0.0.0.0`, the API is exposed on the LAN.

> The bridge currently has **no HTTP authentication**. Its only boundary is the
> authenticated WireGuard peer plus the bind address. Never bind it to a public
> address, and never forward TCP `8787` on a router.

## Mobile

```powershell
cd mobile
npm install
npx expo start
```

For browser preview during development:

```powershell
npm run web
```

Default URLs:

- Web/dev preview: `http://127.0.0.1:8787`
- Physical Android device over the VPN: `http://10.77.77.1:8787`

Build configuration is two variables in `mobile/.env.local` (Git-ignored):

```text
CODEX_MOBILE_GATEWAY=http
CODEX_MOBILE_API_BASE_URL=http://10.77.77.1:8787
```

## Remote Access Setup

On the desktop:

```powershell
winget install --id WireGuard.WireGuard -e
```

On the phone, install the official free **WireGuard** app
(`com.wireguard.android`). No paid VPN service is involved — the desktop is the
server.

The short version of the setup:

1. Generate a host key pair; keep the private key out of the repository, with a
   restricted ACL, and never print it.
2. In the phone's WireGuard app, create a tunnel with address `10.77.77.2/32`
   and let the app generate its own private key.
3. Exchange **public** keys. Set the phone's `AllowedIPs` to `10.77.77.1/32` —
   split tunnel, not `0.0.0.0/0`.
4. Import the host configuration and set the tunnel service to start
   automatically.
5. Bind the bridge to `10.77.77.1` and validate `/health`.
6. In the app: `Settings -> Bridge -> http://10.77.77.1:8787 -> Save URL`.

For access over mobile data, the endpoint depends on your ISP. If your IPv4 is
behind CGNAT, IPv6 is the only zero-cost path: use the **stable** global IPv6
address (the one with `SuffixOrigin = Link`, not the rotating privacy address),
allow inbound UDP `51821` in the router's IPv6 firewall if it is not already
permissive, and keep `AllowedIPs` unchanged.

Validate the whole environment with:

```powershell
.\scripts\validate_wireguard_ready.ps1
```

The complete runbook, including troubleshooting and DDNS, is an internal
document (see below).

## Android APK Build

The complete build path is documented in the interactive guide:

```text
build-guide/index.html
```

Open it directly in a browser after cloning the repo. No local server is needed.
It covers prerequisites, WireGuard setup, `CODEX_MOBILE_*` build variables, APK
generation, install, security tradeoffs, and troubleshooting.

The short version is:

1. Start the bridge bound to the tunnel address and confirm `/health`.
2. Bring up the WireGuard tunnel on both ends and confirm the handshake.
3. Set `CODEX_MOBILE_GATEWAY=http` and `CODEX_MOBILE_API_BASE_URL`.
4. Build the native Android project and release APK.
5. Install the APK and validate on Wi-Fi and mobile data.

## Workspaces

Allowed workspaces are read from:

```text
config/workspaces.allowlist
```

The file is ignored by Git. Use `config/workspaces.allowlist.example` as the
template. At runtime, `CODEX_BRIDGE_WORKSPACE_ALLOWLIST` takes precedence — the
effective list is the one printed in the `bridge_listening` startup event.

The bridge also exposes workspace add/remove/restore endpoints, so the mobile app
can update the allowlist without rebuilding the APK. Because those endpoints are
unauthenticated today, treat anything that can reach the bridge as able to widen
its own scope.

## API

The bridge exposes an HTTP/SSE contract on the tunnel address. The canonical
endpoint reference is in `backend/README.md`.

Start with:

- `GET /health`
- `GET /v1/capabilities`

The current API includes thread creation/listing/history, run streaming and
reattach, cancellation, workspace management, filesystem browsing, model/config
settings, account/rate-limit reads, apps, skills, MCP server/resource access, and
approvals. It also stages file attachments: `POST /v1/uploads` stores a base64
payload on the host, and `input_items: [{ type: "attachment", name, path }]`
forwards it to the run as a `localImage` (images) or a path reference (other
files).

## Current State

The bridge and mobile app are implemented and operational for the internal
Android flow, over WireGuard, validated on both Wi-Fi and mobile data. Current
functionality includes workspace selection, conversation management, streaming
chat, Markdown rendering, activity/tool timeline, human-in-the-loop approvals,
cancellation, model and reasoning controls, account limits, execution presets,
apps/skills/MCP navigation, and settings.

The main remaining work is application-layer authorization on the bridge —
currently absent by an explicit, time-boxed decision — plus running the bridge
as a persistent service.
